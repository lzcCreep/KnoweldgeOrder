# 后端任务说明

本文直接交给后端开发使用。公共事实来源是 [整体架构.md](整体架构.md)、[数据与文件策略.md](数据与文件策略.md)、[前后端接口契约.md](前后端接口契约.md) 和 [后端实施清单.md](后端实施清单.md)。

## 你负责什么

Spring Boot 后端是云端可信边界，负责：

- 登录、用户、知识空间和权限。
- SQLite 业务对象与 PostgreSQL 的增量同步协议。
- 文件上传、对象存储、解析和摄取任务。
- LangChain4j 切块、BGE-M3 向量化和 pgvector 索引。
- 检索、Chat Model、SSE 回答和引用。
- MCP 工具依赖的受控 API、鉴权与审计。

后端不管理用户电脑上的绝对路径；`D:\...` 等本机路径只保存在 SQLite。

## 数据职责

```text
PostgreSQL：用户、空间、笔记、文档元数据、同步版本、任务、会话、引用
对象存储：需要上传云端的 PDF/DOCX/图片等原件
pgvector：chunk 文本、1024 维向量、文档 ID、页码和权限 metadata
```

不要把 PDF 二进制写进向量表。不要把 pgvector 当成原文事实来源。

## 同步 API

需要新增批量增量协议，例如：

```text
POST /api/v1/sync/push
GET  /api/v1/sync/pull?cursor=...
```

每条变更至少包含：

```json
{
  "entity_type": "note",
  "entity_id": "UUID",
  "operation": "upsert",
  "base_revision": 3,
  "client_updated_at": "2026-08-13T06:00:00Z",
  "payload": {}
}
```

服务端逐条返回 `accepted`、`conflict` 或 `rejected`。冲突必须返回服务器版本，不能用最后写入者静默覆盖正文。

## 文件摄取管线

```text
上传/登记文件
  -> 保存原件或 object_key
  -> documents 写元数据
  -> ingestion_jobs queued
  -> DocumentParser 解析
  -> parse_status=ready
  -> DocumentSplitter 切块
  -> BGE-M3 批量 embedding
  -> pgvector 写入
  -> index_status=ready
```

必须把 `parse_status`、`index_status`、`sync_status` 分开。当前 `DocumentService.process()` 只流转状态，尚未调用 `RagPipeline`，下一步要真正接通。

解析器优先级：

1. Markdown/TXT：保留现有实现。
2. PDF：Apache PDFBox，保留页码。
3. DOCX：Apache POI，保留标题和段落。
4. HTML：Jsoup 清洗。
5. 扫描 PDF/图片：OCR，后续阶段。

## 向量索引要求

- 使用 `BAAI/bge-m3`，当前维度 `1024`。
- metadata 至少包含 owner/space/document/chunk/page/title/index_version。
- 更新文档时先构建新索引，再原子切换版本，避免检索空窗。
- 删除文档时必须按 document ID 清理 chunks。
- 模型、维度、切块参数变化后支持全量重建。
- 向量写入失败不能删除原件和解析结果。

## 删除 API

建议显式拆分：

```text
DELETE /api/v1/documents/{id}/index
DELETE /api/v1/documents/{id}/cloud
DELETE /api/v1/documents/{id}?scope=all
```

- `/index`：只清理 pgvector，`index_status=none`。
- `/cloud`：软删除云端业务记录、清理向量、按保留策略处理对象。
- `scope=all`：需要确认 token/幂等键/审计；本机源文件仍由桌面端最终删除。

当前 `DELETE /api/v1/documents/{id}` 仅软删除 `documents`，必须在向量正式接通前补齐一致性处理。

## RAG API

```text
POST /api/v1/retrieval/search
POST /api/v1/chat
GET  /api/v1/chat/stream
```

响应必须返回结构化引用：

```json
{
  "answer": "...",
  "citations": [
    {
      "document_id": "doc_uuid",
      "chunk_id": "chunk_uuid",
      "title": "文档标题",
      "page": 3,
      "quote": "引用片段",
      "score": 0.86
    }
  ]
}
```

低于相关度阈值时返回无足够依据，不允许无引用编造。

## MCP 接口适配

独立 `mcp-server` 不直接访问数据库。后端需要提供稳定的只读 API，并允许 MCP 传递用户授权：

- 搜索笔记必须带 space/user 范围。
- 获取笔记必须验证 owner/role。
- 工具调用写审计日志。
- 写工具后续必须带确认和幂等键。

当前 MCP 的 `/api/notes/search`、`/api/notes/{id}` 与真实 `/api/v1` API 不一致，需要在联调阶段修正。

## 当前优先级

1. Flyway 和正式 schema。
2. 增量同步 API 与冲突协议。
3. 文档三状态和对象存储字段。
4. PDFBox/POI 解析器。
5. `DocumentService -> RagPipeline -> pgvector` 真正闭环。
6. 删除向量一致性。
7. 检索、Chat、SSE、引用。
8. MCP 路径和授权联调。

## 验收条件

- 上传接口返回任务而非伪装同步完成。
- 文档能从原件重建解析结果与向量。
- 更新、删除不会留下孤立向量。
- 同步冲突有确定响应。
- RAG 回答带可回到原文的引用。
- PostgreSQL/BGE-M3 临时不可用不会导致本地数据丢失。
