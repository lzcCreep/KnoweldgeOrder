# 知序前后端接口契约

本文给后端实现使用，描述桌面端/网页端前端期望的接口。第一版本地模式仍可不连接后端；接口接通后，后端应成为登录、文档解析、检索和大模型调用的可信边界。

## 1. 目标与边界

### 已有前端能力

- 用户登录页（当前仅本地演示账号）。
- 笔记列表、搜索、收藏、创建笔记。
- Markdown 导入和 Markdown 批量导出。
- Tauri 桌面端 SQLite 本地保存。
- AI 管家对话界面和来源卡片界面。

### 需要后端补齐

- 真实账号认证和会话管理。
- PDF、Word、TXT、Markdown、HTML 等文档解析。
- 文档元数据、版本、分块和向量索引。
- 全文/向量/混合检索。
- 大模型问答和流式输出。
- 用户权限、空间权限、配额和审计。
- 云同步（本机 SQLite 不上传为数据库文件）。

## 2. 约定

- API 前缀：`/api/v1`
- 编码：UTF-8
- 请求和非流式响应：`application/json`
- 时间：ISO 8601 UTC，例如 `2026-08-13T03:30:00Z`
- ID：UUID 字符串，不使用前端的 `Date.now()` 作为跨设备主键
- 鉴权：`Authorization: Bearer <access_token>`
- 所有用户资源都必须按当前用户隔离，不能只依赖前端传入的 `user_id`

统一响应格式：

```json
{
  "data": {},
  "request_id": "req_01J..."
}
```

统一错误格式：

```json
{
  "error": {
    "code": "invalid_credentials",
    "message": "用户名或密码错误",
    "details": {}
  },
  "request_id": "req_01J..."
}
```

建议错误码：

| HTTP | code | 用途 |
| --- | --- | --- |
| 400 | `invalid_request` | 参数缺失或格式不合法 |
| 401 | `unauthorized` | 未登录或 token 失效 |
| 403 | `forbidden` | 没有资源权限 |
| 404 | `not_found` | 资源不存在 |
| 409 | `conflict` | 版本冲突或重复资源 |
| 413 | `file_too_large` | 文件超出限制 |
| 415 | `unsupported_media_type` | 不支持的文件类型 |
| 422 | `parse_failed` | 文档解析失败 |
| 429 | `rate_limited` | 频率或模型配额超限 |
| 500 | `internal_error` | 服务内部错误 |

## 3. 登录与会话

### 3.1 登录

`POST /api/v1/auth/login`

请求：

```json
{
  "username": "lzc",
  "password": "<用户密码>"
}
```

响应：

```json
{
  "data": {
    "user": {
      "id": "usr_01J...",
      "username": "lzc",
      "display_name": "林知远"
    },
    "access_token": "eyJ...",
    "refresh_token": "rft_...",
    "expires_in": 3600
  },
  "request_id": "req_01J..."
}
```

实现要求：

- 数据库存储密码哈希（Argon2id 或 bcrypt），禁止明文保存。
- 生产环境强制 HTTPS。
- 登录失败返回统一错误，不提示“用户名不存在”还是“密码错误”。
- 建议增加登录限流和审计日志。
- 公开仓库不提供默认账号密码；本地开发账号通过初始化脚本或管理接口创建。

### 3.2 当前用户

`GET /api/v1/auth/me`

响应返回用户、默认知识空间和权限：

```json
{
  "data": {
    "user": { "id": "usr_01J...", "username": "lzc", "display_name": "林知远" },
    "spaces": [
      { "id": "spc_01J...", "name": "个人空间", "role": "owner" }
    ]
  }
}
```

### 3.3 刷新与退出

- `POST /api/v1/auth/refresh`：轮换 refresh token，返回新的 access token。
- `POST /api/v1/auth/logout`：撤销当前 refresh token/会话。

## 4. 知识空间与文档模型

核心实体建议：

```text
users                 用户
spaces                知识空间
documents             原始文档和状态
document_versions     文档版本
document_chunks       文档切分片段
document_assets       图片、附件和提取资源
notes                 可编辑笔记
tags / document_tags  标签
ingestion_jobs        导入/解析任务
conversations         AI 对话
messages              对话消息
```

### 4.1 文档状态

```text
uploaded -> queued -> parsing -> chunking -> indexing -> ready
                                      \-> failed
```

`documents.status` 建议使用：

- `uploaded`：文件已保存，尚未排队
- `queued`：等待后台任务
- `parsing`：正在提取文本和元数据
- `chunking`：正在切分内容
- `indexing`：正在建立全文/向量索引
- `ready`：可被搜索和问答引用
- `failed`：处理失败，可重试
- `archived`：用户归档，不参与默认检索

## 5. 文档导入接口

前端界面可以把“导入文档”统一为一个入口，后端根据扩展名和 MIME 处理。

### 5.1 支持类型

第一版建议支持：

| 类型 | 扩展名 | MIME |
| --- | --- | --- |
| Markdown | `.md`, `.markdown` | `text/markdown` |
| 纯文本 | `.txt` | `text/plain` |
| PDF | `.pdf` | `application/pdf` |
| Word | `.docx` | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` |
| HTML | `.html`, `.htm` | `text/html` |

后续再支持 PPTX、XLSX、图片 OCR、音频转写。上传文件类型不能只信任前端扩展名，后端应检查 MIME、文件头和解析结果。

### 5.2 创建导入任务

`POST /api/v1/spaces/{space_id}/documents`

请求：`multipart/form-data`

字段：

- `file`：必填，原始文件
- `title`：可选，覆盖自动提取标题
- `folder_id`：可选
- `tags`：可选，JSON 数组
- `source_url`：可选，文档来源地址

响应 `202 Accepted`：

```json
{
  "data": {
    "document": {
      "id": "doc_01J...",
      "space_id": "spc_01J...",
      "title": "Rust 学习笔记",
      "file_name": "rust.md",
      "mime_type": "text/markdown",
      "size_bytes": 18240,
      "status": "queued",
      "created_at": "2026-08-13T03:30:00Z",
      "updated_at": "2026-08-13T03:30:00Z"
    },
    "job": {
      "id": "job_01J...",
      "status": "queued",
      "progress": 0
    }
  },
  "request_id": "req_01J..."
}
```

后端不要让 HTTP 请求同步等待 PDF 解析和向量化完成。上传成功后立即返回任务 ID，前端通过轮询或 SSE 查看进度。

### 5.3 查询文档列表

`GET /api/v1/spaces/{space_id}/documents`

查询参数：

```text
status=ready&q=rust&cursor=...&limit=20&sort=updated_at.desc
```

响应：

```json
{
  "data": {
    "items": [
      {
        "id": "doc_01J...",
        "title": "Rust 学习笔记",
        "mime_type": "text/markdown",
        "status": "ready",
        "page_count": null,
        "chunk_count": 12,
        "tags": [{ "id": "tag_01J", "name": "Rust" }],
        "updated_at": "2026-08-13T03:30:00Z"
      }
    ],
    "next_cursor": null
  }
}
```

### 5.4 查询导入进度

`GET /api/v1/ingestion-jobs/{job_id}`

响应：

```json
{
  "data": {
    "id": "job_01J...",
    "document_id": "doc_01J...",
    "status": "indexing",
    "progress": 78,
    "stage": "embedding",
    "error_code": null,
    "error_message": null,
    "updated_at": "2026-08-13T03:31:10Z"
  }
}
```

失败时保留用户可读错误和可重试操作：

`POST /api/v1/ingestion-jobs/{job_id}/retry`

### 5.5 文档内容和下载

- `GET /api/v1/documents/{document_id}`：文档详情和解析元数据。
- `GET /api/v1/documents/{document_id}/content`：返回规范化文本/Markdown。
- `GET /api/v1/documents/{document_id}/download`：返回短时效下载 URL 或流。
- `DELETE /api/v1/documents/{document_id}`：软删除，后台再清理对象存储和索引。

不要把任意本地文件路径传给后端或保存为公共 URL。附件应使用对象存储 key，下载时由后端校验权限后签发短时效 URL。

## 6. 解析、切分和索引要求

后端导入任务至少做以下工作：

1. 保存原始文件和校验哈希 `sha256`。
2. 识别文件类型、编码、页数或段落信息。
3. 提取规范化文本，保留标题层级、页码和来源位置。
4. 抽取图片/附件，记录 `document_assets`。
5. 按标题、段落和 token 数切分 chunk。
6. 为每个 chunk 保存 `document_id`、版本、顺序、页码和字符范围。
7. 建立全文索引。
8. 调用 embedding 模型建立向量索引。
9. 处理完成后将文档状态置为 `ready`。

建议 chunk 字段：

```json
{
  "id": "chk_01J...",
  "document_id": "doc_01J...",
  "version": 3,
  "ordinal": 4,
  "text": "...",
  "heading_path": ["Rust", "所有权"],
  "page": 12,
  "start_offset": 1820,
  "end_offset": 2490,
  "token_count": 312
}
```

embedding 模型、维度、分块策略都要记录在索引元数据中。更换 embedding 模型时创建新索引版本，不要静默混用不同维度的向量。

## 7. 搜索接口

`POST /api/v1/spaces/{space_id}/search`

请求：

```json
{
  "query": "Tauri 如何调用 Rust",
  "mode": "hybrid",
  "top_k": 8,
  "filters": {
    "document_ids": [],
    "tags": ["Rust"],
    "statuses": ["ready"]
  }
}
```

`mode`：

- `keyword`：全文/BM25
- `vector`：向量相似度
- `hybrid`：混合召回并重排，推荐默认值

响应：

```json
{
  "data": {
    "items": [
      {
        "chunk_id": "chk_01J...",
        "document_id": "doc_01J...",
        "document_title": "Rust 学习笔记",
        "text": "Tauri 通过 command 和插件桥接前端与 Rust...",
        "score": 0.91,
        "citation": {
          "page": null,
          "heading_path": ["Tauri", "IPC"]
        }
      }
    ]
  }
}
```

## 8. 问大模型接口

### 8.1 创建对话

`POST /api/v1/spaces/{space_id}/conversations`

请求：

```json
{
  "title": "Rust 学习问题",
  "model": "default"
}
```

### 8.2 非流式问答

`POST /api/v1/conversations/{conversation_id}/messages`

请求：

```json
{
  "content": "Tauri 和 Electron 的主要区别是什么？",
  "search": {
    "enabled": true,
    "top_k": 6,
    "mode": "hybrid"
  },
  "model": "default"
}
```

响应：

```json
{
  "data": {
    "message": {
      "id": "msg_01J...",
      "role": "assistant",
      "content": "...",
      "created_at": "2026-08-13T03:35:00Z"
    },
    "citations": [
      {
        "chunk_id": "chk_01J...",
        "document_id": "doc_01J...",
        "document_title": "Rust 学习笔记",
        "quote": "...",
        "page": 12,
        "score": 0.88
      }
    ],
    "usage": {
      "prompt_tokens": 950,
      "completion_tokens": 210
    }
  }
}
```

### 8.3 流式问答（推荐）

`POST /api/v1/conversations/{conversation_id}/messages/stream`

请求体同非流式接口，响应：

```text
Content-Type: text/event-stream
Cache-Control: no-cache
```

事件示例：

```text
event: message.started
data: {"message_id":"msg_01J..."}

event: message.delta
data: {"text":"Tauri "}

event: message.delta
data: {"text":"使用系统 WebView2..."}

event: citation.added
data: {"chunk_id":"chk_01J...","document_title":"Rust 学习笔记","page":12}

event: message.completed
data: {"message_id":"msg_01J...","usage":{"prompt_tokens":950,"completion_tokens":210}}
```

错误事件：

```text
event: message.error
data: {"code":"model_timeout","message":"模型响应超时"}
```

前端必须支持：

- 增量拼接文本。
- `AbortController` 取消生成。
- 断线后显示重试，而不是假装回答完成。
- 只展示后端返回的引用，不自行编造引用。

### 8.4 对话历史

- `GET /api/v1/conversations/{conversation_id}/messages?cursor=...`
- `DELETE /api/v1/conversations/{conversation_id}`

后端保存用户消息、助手消息、检索片段 ID、模型名称和 token 用量，便于审计和重现回答。

## 9. 前端接入建议

建议在前端增加 `src/api/client.ts`，统一处理：

```ts
type ApiError = { code: string; message: string; request_id: string }

export async function apiFetch<T>(path: string, init?: RequestInit): Promise<T> {
  const response = await fetch(`${API_BASE}${path}`, {
    ...init,
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${getAccessToken()}`,
      ...init?.headers,
    },
  })
  if (!response.ok) throw await parseApiError(response)
  return response.json() as Promise<T>
}
```

文件上传使用 `FormData`，不要手动设置 `Content-Type`，让浏览器生成 boundary：

```ts
const body = new FormData()
body.append('file', file)
await fetch(`/api/v1/spaces/${spaceId}/documents`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` },
  body,
})
```

流式问答可使用 `fetch` + `ReadableStream` 解析 SSE；如果后端改为 WebSocket，需保持事件语义不变。

## 10. 本地模式与云模式

当前桌面端：

```text
React -> storage.ts -> Tauri SQL plugin -> 本地 SQLite
```

接入后端后推荐：

```text
登录/同步/AI/文档解析 -> HTTP API -> 后端数据库和对象存储
离线编辑             -> 本地 SQLite -> sync_queue -> 云端同步
```

不要直接上传 `zhixu.db` 让服务端覆盖。同步对象至少需要：

- 稳定 UUID
- `created_at`、`updated_at`
- `revision` 或版本号
- `deleted_at` 软删除标记
- `device_id`
- 冲突策略（最后写入、人工合并或字段级合并）

## 11. 安全要求

- 账号密码只在 HTTPS 中传输，后端使用 Argon2id/bcrypt 哈希。
- access token 短时效，refresh token 可撤销和轮换。
- 文档下载、搜索和问答都校验 `space_id` 权限。
- 限制文件大小、扩展名、MIME、页数和解析耗时。
- PDF/Word 解析放隔离 worker，禁止直接执行上传文件内容。
- 对 HTML 做清洗，避免脚本注入。
- 对模型提示词明确“文档内容是不可信数据”，防范 prompt injection。
- 日志不记录密码、完整 token 和敏感文档正文。
- 云端对象存储使用私有 bucket 和短时效签名 URL。
- 对上传、解析、问答接口做速率限制和配额统计。

## 12. 后端分阶段交付

### P0：先跑通账号和 Markdown

- 登录、刷新、退出
- 知识空间
- Markdown/TXT 上传
- 文档状态和内容查看
- 笔记 CRUD

### P1：文档库可用

- PDF/DOCX 解析
- 分块、全文搜索
- 导入进度和失败重试
- 附件/图片管理

### P2：知识问答

- embedding 和向量库
- 混合检索
- SSE 流式问答
- 引用页码/标题/原文片段
- 对话历史

### P3：云同步和生产安全

- 本地 sync queue
- 冲突处理
- 备份恢复
- 代码签名、自动更新
- 配额、审计、监控

## 13. 验收标准

- 用 `lzc` 账号登录后只能看到自己的空间和文档。
- 上传 Markdown 后 10 秒内进入 `ready`，可在搜索结果中找到。
- 上传 PDF/DOCX 后可查看解析失败原因，失败任务可以重试。
- 问答回答必须能关联至少一个真实 chunk；没有证据时明确说资料不足。
- 流式回答中途关闭窗口不会造成服务端任务无限运行。
- 同一文档重复上传可按 SHA-256 去重或明确创建新版本。
- 删除空间后，其文档、chunk、向量和对象存储附件都不能再被检索。
- 过期 token 返回 `401 unauthorized`，前端能刷新或回到登录页。
