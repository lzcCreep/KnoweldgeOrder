# 数据与文件策略

## 核心原则

1. SQLite 是本地数据，不依赖服务可用性。
2. PostgreSQL 是云端业务副本，通过对象级增量同步维护。
3. pgvector 只保存 AI 检索索引，随时可以从原文重建。
4. 源文件与提取文本、向量是三种不同资产，必须分别管理。
5. 文件上传成功不等于向量索引成功，两者必须有独立状态。

## 文件记录建议字段

```text
id                 稳定 UUID
space_id           知识空间
title              标题
file_name          原文件名
local_path         本地源文件路径，仅保存在本机
object_key         云端对象存储 key，可为空
mime_type          文件类型
size_bytes         大小
sha256             去重与变更检测
parse_status       pending/parsing/ready/failed
index_status       none/queued/indexing/ready/failed
sync_status        local/pending/synced/conflict
parser_version     解析器版本
embedding_model    BAAI/bge-m3
index_version      向量索引版本
deleted_at         软删除时间
```

本地路径不能原样同步给其他设备，因为每台机器的目录不同。云端只同步相对逻辑信息和对象存储 key。

## 推荐存储布局

用户设置一个根目录，例如：

```text
D:\KnowledgeFiles
├─ originals\2026\08\<document-id>\原始文件.pdf
├─ exports\
└─ backups\
```

不要直接按原文件名平铺，否则同名文件会覆盖。使用 document ID 建目录，文件名用于显示。

## 导入状态机

```text
selected
  -> source_saved
  -> metadata_created
  -> uploaded（可选）
  -> parsing
  -> parsed
  -> indexing
  -> ready

任一步失败 -> failed + error_code + error_message -> retry
```

UI 应分别显示“源文件已保存”“云端已同步”“AI 可检索”，不能只显示一个模糊的“上传成功”。

## 查看文件

知识文件提供两种查看方式：

- **打开源文件**：Tauri 使用系统默认程序打开本机 PDF、DOCX、Markdown 等原件。
- **查看提取文本**：调用后端 `/api/v1/documents/{id}/content`，展示用于搜索和向量化的纯文本。

SQLite 的 `document_sources` 表保存 `document_id -> local_path` 映射。绝对路径只属于当前设备，不同步到 PostgreSQL；其他设备没有同一源文件时，“打开源文件”按钮应禁用，但如果云端有解析文本，仍可以查看提取文本。

## PDF 是否直接进入向量库

不直接进入。正确流程是：

```text
PDF 二进制 -> 源文件目录/对象存储
PDF 解析文本 -> 文档内容与解析结果
文本切块 -> BGE-M3 -> pgvector
```

pgvector 中保存 chunk 文本、向量、文档 ID、页码、段落和权限 metadata。PDF 二进制没有放进向量列的价值。

## 删除策略

删除接口建议使用显式 scope：

```text
DELETE /api/v1/documents/{id}/index       # 仅移出 AI 知识库
DELETE /api/v1/documents/{id}/cloud       # 删除云端业务副本和索引
DELETE /api/v1/documents/{id}/local       # 桌面端删除本地记录
DELETE /api/v1/documents/{id}?scope=all   # 彻底删除，强确认
```

当前后端 `DELETE /api/v1/documents/{id}` 只软删除 `documents`，尚未清理向量和源文件，必须在真正索引接通前完善。

## 同步策略

- 每个对象使用 UUID，不能依赖自增 ID 或 `Date.now()`。
- 每条记录包含 `revision`、`updated_at`、`deleted_at`。
- SQLite 保存 `sync_queue`，本地事务与队列写入一起提交。
- 上传按批次发送变更，服务端逐条返回 accepted/conflict。
- 冲突不能静默覆盖：正文进入冲突副本或让用户选择。
- 附件使用哈希去重，文件上传与业务元数据同步分开。

## 隐私设置建议

- 默认保留本地源文件，默认不删除原件。
- 每次加入 AI 知识库可选择仅本地索引或云端索引。
- 云端 Chat Model 只接收必要 chunk，并提供“完全本地”开关。
- 日志不得记录文件全文、向量、密码和完整 Prompt。
