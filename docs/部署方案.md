# 知序部署方案

更新时间：2026-08-17

## 1. 结论

当前版本适合两种部署：

1. **纯离线桌面版**：只安装 Tauri 客户端，不部署 Spring Boot、PostgreSQL 或 pgvector。笔记保存在本机 SQLite，Markdown/TXT 保存在用户选择的目录；如需断网 AI，再部署本机 OpenAI 兼容模型。
2. **单实例私有云版**：Tauri/浏览器客户端连接一套 Spring Boot + PostgreSQL/pgvector 服务。当前文件服务仍依赖服务器本地目录，因此推荐先使用单实例，暂不做多后端节点。

当前不建议直接做公网多租户或多节点生产部署。完整上线前仍需补齐对象存储、Flyway、跨设备增量同步、运行时后端地址、限流审计和凭据安全存储。

## 2. 推荐拓扑

```text
Windows Tauri / Web Browser
          |
        HTTPS 443
          |
   Nginx / Caddy
          |
 Spring Boot :8080
    |       |       |       \
    |       |       |        -> server knowledge-files (current single-node storage)
    |       |       -> OpenAI compatible Chat Model (login mode)
    |       -> BGE-M3 :8100 (cloud RAG)
    -> PostgreSQL + pgvector :5432

离线模式下，客户端按本机设置直接访问 OpenAI 兼容 Chat Model；登录模式由 Spring Boot 代为调用。
```

只对外开放 `443`。`8080`、`5432` 和 `8100` 应只绑定回环地址或内部网络。

## 3. 方案 A：纯离线桌面版

### 3.1 适用范围

- 单台 Windows 电脑使用。
- 不需要多设备同步、云端空间和云端文档。
- 笔记、待办、设置和知识文件必须留在本机。

### 3.2 构建环境

- Node.js `20.19.x`
- Rust stable
- Visual Studio Build Tools（Desktop development with C++）
- WebView2 Runtime

```powershell
cd D:\KnowledgeOrder\frontend
npm ci
npm run lint
npm run build
npm run app:build
```

NSIS 安装包输出到：

```text
frontend\src-tauri\target\release\bundle\nsis\
```

### 3.3 首次配置

1. 安装并打开知序。
2. 选择“离线进入本地知识库”。
3. 在“设置 -> 通用”中选择稳定的数据目录，例如 `D:\ZhixuData\knowledge-files`。
4. 如需 AI，填写本机或可访问的 OpenAI 兼容服务 URL、API Key 和模型名。
5. 完全断网使用时，模型服务也必须运行在本机。

### 3.4 备份

必须同时备份 SQLite 和知识库文件目录：

```text
<知序安装目录>\database\zhixu.db
D:\ZhixuData\knowledge-files\
```

安装目录不可写时，SQLite 会回退到 `%APPDATA%\com.zhixu.desktop\zhixu.db`。备份前先在实际目录确认文件，关闭客户端后复制整个 `database` 目录；如需在运行中备份，必须同时复制 `zhixu.db-wal` 和 `zhixu.db-shm`。升级或卸载可能清理安装目录，因此安装版数据库必须纳入独立备份。

## 4. 方案 B：单实例私有云版

### 4.1 服务器前置条件

- Linux 或 Windows Server
- Java 17
- Maven 3.9+
- PostgreSQL 18 + pgvector 0.8.6（可使用 Docker）
- Nginx 或 Caddy
- 可持久化的后端文件目录
- 可选：BGE-M3 OpenAI 兼容 Embedding 服务

仓库当前没有 Maven Wrapper，也没有可直接启动的 Docker Compose；部署机必须安装 `mvn`，数据库和反向代理需要单独部署。

### 4.2 PostgreSQL + pgvector

单机 Docker 示例：

```bash
docker run -d \
  --name zhixu-postgres \
  --restart unless-stopped \
  -e POSTGRES_DB=zhixu \
  -e POSTGRES_USER=zhixu \
  -e POSTGRES_PASSWORD='REPLACE_WITH_STRONG_PASSWORD' \
  -p 127.0.0.1:5432:5432 \
  -v zhixu-postgres-data:/var/lib/postgresql/data \
  pgvector/pgvector:0.8.6-pg18-trixie
```

Spring Boot 启动时会执行 `backend/src/main/resources/schema.sql`，创建当前业务表和 `vector` 扩展。当前仍使用 `schema.sql`，正式生产升级前应迁移到 Flyway，避免结构演进不可审计。

### 4.3 后端环境变量

至少配置以下变量，不要把真实密码提交到仓库：

```bash
export DATABASE_URL='jdbc:postgresql://127.0.0.1:5432/zhixu'
export DATABASE_USERNAME='zhixu'
export DATABASE_PASSWORD='REPLACE_WITH_STRONG_PASSWORD'

export PGVECTOR_HOST='127.0.0.1'
export PGVECTOR_PORT='5432'
export PGVECTOR_DATABASE='zhixu'
export PGVECTOR_USER='zhixu'
export PGVECTOR_PASSWORD='REPLACE_WITH_STRONG_PASSWORD'
export PGVECTOR_TABLE='knowledge_embeddings'
export PGVECTOR_DIMENSION='1024'

export EMBEDDING_BASE_URL='http://127.0.0.1:8100/v1'
export EMBEDDING_API_KEY='not-required'
export EMBEDDING_MODEL='BAAI/bge-m3'

export SOURCE_DIRECTORY='/srv/zhixu/knowledge-files'
export SERVER_PORT='8080'
```

生产环境必须显式覆盖数据库密码；不能依赖 `application.yml` 中的开发默认值。

### 4.4 构建与启动后端

```bash
cd backend
mvn clean test
mvn clean package -DskipTests
java -jar target/zhixu-backend-0.1.0.jar
```

建议使用 systemd 或 Windows Service 托管，并设置：

- 异常自动重启。
- 独立的非管理员运行账户。
- `SOURCE_DIRECTORY` 的最小读写权限。
- 日志轮转和磁盘告警。
- JVM 内存上限，例如 `-Xms256m -Xmx1g`。

探活接口：

```text
GET http://127.0.0.1:8080/api/health
```

### 4.5 HTTPS 反向代理

Nginx 示例：

```nginx
server {
    listen 443 ssl http2;
    server_name zhixu.example.com;

    ssl_certificate     /etc/letsencrypt/live/zhixu.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/zhixu.example.com/privkey.pem;

    client_max_body_size 11m;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

### 4.6 构建云端桌面客户端

当前后端地址通过前端构建变量写入：

```powershell
cd D:\KnowledgeOrder\frontend
$env:VITE_API_BASE_URL='https://zhixu.example.com'
npm ci
npm run app:build
```

打包远程地址前，还必须把该 HTTPS 域名加入 `frontend/src-tauri/tauri.conf.json` 的 `connect-src`。Tauri HTTP capability 已允许 `http://**` 和 `https://**`，但 WebView 的 CSP 仍需要允许实际域名。

当前设置页展示云端连接状态和同步策略，但不能在运行时切换后端地址。若需要一个安装包连接不同服务器，应先增加运行时服务地址配置、地址校验和重启登录流程。

## 5. Web 与手机浏览器部署

可以把 Vite 构建产物部署到与 API 相同的域名：

```bash
cd frontend
npm ci
npm run build
```

将 `frontend/dist` 交给 Nginx，并让 `/api/` 反向代理到 Spring Boot。浏览器模式使用 `localStorage`，不是 Tauri SQLite，也不能扫描服务器或手机的任意文件目录。

当前手机页面是响应式 Web，不是原生 App。首次加载和刷新仍需要访问 Web 服务器；没有 Service Worker 时不能保证完全断网启动。要发布 Android/iOS 安装包，需要另行初始化 Tauri mobile、配置安全存储、HTTPS 和应用签名。

## 6. 当前文件部署限制

这是上线前最重要的限制：

1. 桌面端已经先把 Markdown/TXT 保存到用户本机目录。
2. 上传云端时，后端又把上传内容写入服务器文件目录，并把文本保存到 PostgreSQL `documents.content`。
3. 当前上传请求仍携带客户端的 `local_directory`，后端可能使用该值作为服务器路径。

因此远程 Linux、多客户端和多节点环境上线前，应改为：

- 后端忽略客户端绝对路径，只使用服务器 `SOURCE_DIRECTORY`；或
- 原件写入 MinIO/S3，PostgreSQL 只保存 object key、元数据和解析文本；
- 客户端绝对路径只保存在本机 SQLite `document_sources`，永不上传为服务器路径。

在这项改造完成前，私有云建议部署为单后端实例，并先用测试目录验证上传路径，不能直接扩容多个后端节点。

## 7. AI 与 RAG 部署边界

- Chat Model URL/Key/模型名由每台客户端配置。
- 离线模式由客户端直接调用 Chat Model。
- 登录模式把模型配置随单次请求发送给 Spring Boot 代理调用，当前不保存到 PostgreSQL。
- 登录模式下，`DocumentService` 通过 LangChain4j 调用 BGE-M3 建立 pgvector 索引；`KnowledgeRetriever` 用同一 Embedding Model 做带用户/空间过滤的 Top-K 检索；`KnowledgeAssistant` 通过 `@SystemMessage`、`@UserMessage` 和 `OpenAiChatModel` 生成回答。
- 当前文档只有在向量写入完成后才会进入 `ready`；失败会保留原文并将任务标记为 `failed`，可再次重试。

只使用离线模式时可以不启动 BGE-M3、PostgreSQL 和 Spring Boot。启用云端知识库 RAG 时，BGE-M3 与 pgvector 是必需服务；没有云端 `ready` 文档时，普通云端模型对话会跳过 embedding 检索。

## 8. 安全要求

- 外部访问必须使用 HTTPS。
- PostgreSQL、Embedding 和 Spring Boot 原始端口不暴露公网。
- 数据库和 Embedding 服务密钥通过环境变量或密钥管理服务注入；用户 Chat Model Key 当前随请求传给后端，日志不得记录请求体，后续应迁移到系统凭据库或服务端密钥引用。
- 创建真实用户时使用强密码，不提交默认账号密码。
- 限制上传大小和允许的扩展名；当前后端只允许 UTF-8 Markdown/TXT。
- 对登录失败、上传失败、同步冲突和磁盘空间设置监控。
- 客户端模型 API Key 当前是本机明文配置，生产版应迁移到 Windows Credential Manager、macOS Keychain 或移动端安全存储。

## 9. 备份与恢复

### 9.1 云端

每日备份：

```bash
pg_dump -Fc -h 127.0.0.1 -U zhixu -d zhixu -f /backup/zhixu-$(date +%F).dump
```

同时备份 `SOURCE_DIRECTORY`。恢复时数据库和文件目录应恢复到同一时间点。

### 9.2 客户端

备份：

- `<知序安装目录>\database\zhixu.db`（安装目录不可写时回退到 `%APPDATA%\com.zhixu.desktop\zhixu.db`）
- 用户设置的知识库文件目录

云端备份不能替代客户端备份，因为尚未同步的笔记、设置、分类和本机文件可能只存在当前设备。

## 10. 上线验收清单

- `/api/health` 返回成功。
- HTTPS 证书有效，HTTP 自动跳转 HTTPS。
- 新用户可以登录并读取自己的空间，不能访问其他用户数据。
- 新建笔记立即显示本机已保存，随后变为云端已同步。
- 断开后端仍可新建和编辑，恢复后能够重试同步。
- Markdown/TXT 先落本机目录，再按开关上传云端。
- AI 未配置时不返回模拟结果；配置后引用来源类型正确。
- PostgreSQL 和文件目录均完成备份与恢复演练。
- 服务器重启后 Spring Boot、数据库和反向代理自动恢复。
- 上传 Markdown/TXT 后能够完成向量摄取并进入 `ready`，AI 返回的云端来源类型和标题正确。
