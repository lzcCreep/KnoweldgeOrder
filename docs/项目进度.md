# 项目进度

更新时间：2026-08-13。

## 总体判断

项目已经越过纯原型阶段，具备桌面壳、真实后端登录、笔记 CRUD 和文档任务骨架。但核心产品闭环“本地优先同步 + 文件解析 + pgvector 检索 + 带引用问答”尚未完成。

粗略按最终第一版范围计算，整体约 **45%**。这个数字只用于排期，不能代表每个模块质量一致。

## 已完成

- React + TypeScript + Vite 工作台。
- Tauri 2 桌面工程、Windows 构建文档、SQLite 基础存储。
- Spring Boot 3.4 / Java 17 工程。
- 真实登录、会话、知识空间、笔记 CRUD、搜索、收藏和乐观锁。
- Markdown/TXT 文件上传、文档列表、软删除、摄取任务与重试 API。
- Tauri 源文件目录设置、源文件路径映射、系统默认程序打开和提取文本预览。
- 本地 BGE-M3 OpenAI 兼容接口配置，1024 维。
- PostgreSQL + pgvector 配置与 LangChain4j 摄取骨架。
- MCP 独立项目、stdio 和三个只读工具定义。
- 公共中文文档中心。

## 当前最高优先级

1. 把桌面 SQLite 改成真正 CRUD，建立 UUID、revision、deleted_at 和 `sync_queue`。
2. 定义 SQLite -> PostgreSQL 增量同步 API 与冲突处理。
3. 为文档记录增加本地路径、对象 key、parse/index/sync 三组状态。
4. 让 `DocumentService.process()` 真正调用解析器和 `RagPipeline`。
5. 删除文档时按范围清理 pgvector、云端记录和本地文件。
6. 接入 PDFBox/POI，完成 PDF/DOCX 文本提取。
7. 实现检索 API、低相关拒答、Chat Model、SSE 和引用。
8. 适配 MCP 工具到真实 `/api/v1` 路径并加入授权传递。

## 已知技术债

- 后端仍使用 `schema.sql`，应迁移到 Flyway。
- PostgreSQL 密码已从仓库默认值移除，本地启动必须通过环境变量提供。
- `documents.content` 当前保存完整文本，未来需区分原件、解析文本和对象存储。
- 当前后端删除文档只软删除业务记录，未清理向量。
- 前端登录后直接加载 PostgreSQL 笔记，尚未以 SQLite 为事实来源。
- MCP `search_notes/get_note` 路径与真实后端 `/api/v1/spaces/...` 契约尚未一致。
