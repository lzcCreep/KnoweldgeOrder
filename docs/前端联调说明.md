# 前端联调通知

前端路径：`D:\KnowledgeOrder\frontend`。

## 已接入的后端接口

前端已经从本地演示模式切到以下真实 API：

```text
POST /api/v1/auth/login
GET  /api/v1/auth/me
POST /api/v1/auth/logout
GET  /api/v1/spaces/{spaceId}/notes
POST /api/v1/spaces/{spaceId}/notes
PUT  /api/v1/notes/{noteId}
POST /api/v1/spaces/{spaceId}/documents
POST /api/v1/ai/chat
```

本地登录账号需由开发者自行创建，不在公开仓库内提交默认密码。前端新增笔记先写本机 SQLite 和同步队列，登录后再同步到 PostgreSQL `notes_v1`；Markdown/TXT 云端导入写入 `documents` 和 `ingestion_jobs`。

## 当前联调边界

后端当前已实现登录、空间基础管理、笔记 CRUD/搜索、Markdown/TXT 文档上传、文档内容读取和摄取任务状态查询。笔记数据表是 `notes_v1`；向量维度以 [数据库配置.md](数据库配置.md) 和 [本地嵌入服务.md](本地嵌入服务.md) 为准（BGE-M3，1024 维）。

文档上传会把文件原文写入 `documents`，并创建 `ingestion_jobs`。异步任务通过 `RagPipeline` 写入 `knowledge_embeddings`，成功后状态才变为 `ready`。`POST /api/v1/ai/chat` 由 `KnowledgeRetriever` 按用户和空间进行 pgvector Top-K 检索，再通过 LangChain4j 注解式 `KnowledgeAssistant` 调用用户配置的模型。

## 前端期待后端继续实现

- 笔记 CRUD 与向量索引保持一致。
- `POST /api/v1/retrieval/search`。
- SSE 和精确到 chunk/页码的 citations。
- PDF/DOCX 解析。

当前离线 AI 使用本机关键词选材后直连模型；登录模式使用后端 LangChain4j RAG。接口结构继续参考 [前后端接口契约.md](前后端接口契约.md)，表结构、向量维度和配置以公共文档中心的现有记录为准。
