# 前端联调通知

前端路径：`D:\KnoweldgeOrder\frontend`。

## 已接入的后端接口

前端已经从本地演示模式切到以下真实 API：

```text
POST /api/v1/auth/login
GET  /api/v1/auth/me
POST /api/v1/auth/logout
GET  /api/v1/spaces/{spaceId}/notes
POST /api/v1/spaces/{spaceId}/notes
PUT  /api/v1/notes/{noteId}
POST /api/v1/spaces/{spaceId}/documents
```

本地登录账号需由开发者自行创建，不在公开仓库内提交默认密码。前端新增笔记现在写入 PostgreSQL `testdb.notes_v1`；Markdown/TXT 导入写入 `documents` 和 `ingestion_jobs`。

## 当前联调边界

后端当前已实现登录、空间基础管理、笔记 CRUD/搜索、Markdown/TXT 文档上传、文档内容读取和摄取任务状态查询。笔记数据表是 `notes_v1`；向量维度以 [数据库配置.md](数据库配置.md) 和 [本地嵌入服务.md](本地嵌入服务.md) 为准（BGE-M3，1024 维）。

文档上传会把文件原文写入 `documents`，并创建 `ingestion_jobs`。当前异步任务只完成文本校验和状态流转，尚未调用 `RagPipeline`，因此暂时不能据此进行语义检索或 RAG 问答。

## 前端期待后端继续实现

- 文档任务真正调用 `RagPipeline`，写入 `knowledge_embeddings`，并在笔记新增/修改/删除时同步索引。
- 笔记 CRUD 与向量索引保持一致。
- `POST /api/v1/retrieval/search`。
- Chat Model、RAG 问答、SSE 和 citations。
- PDF/DOCX 解析。
- 个人资料更新 API。

当前前端 AI 管家仍是关键词模拟，等检索/Chat API 完成后再切换。接口结构继续参考 [前后端接口契约.md](前后端接口契约.md)，表结构、向量维度和配置以公共文档中心的现有记录为准。
