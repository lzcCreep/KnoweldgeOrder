# 知序学习路线：LangChain4j + RAG

项目统一使用 PostgreSQL + pgvector，不再使用 Qdrant。数据库既保存笔记等业务数据，也保存文本切块的 embedding，适合个人知识库和学习阶段，部署与数据一致性都更简单。

当前开发环境记录见 [数据库配置.md](数据库配置.md)。
整体组件、数据流和部署边界见 [整体架构.md](整体架构.md)。

## 代码应该在哪里写

先从 `src/main/java/com/lzc/zhixu/rag/RagPipeline.java` 读数据摄取链路，再看 `RagConfiguration.java` 理解模型和向量库如何通过 Spring Bean 注入。新增 HTTP 接口放在 `api/`，业务编排放在 `rag/` 或后续新增的 `note/`、`chat/` 模块中；不要把数据库访问、模型调用和 Controller 全写在一个类里。

## 逐层学习顺序

1. **Embedding**：理解文本如何变成固定维度向量，记录模型、维度和费用。
2. **Chunking**：阅读 `RagPipeline`，调整 `500/80` 的 chunk size/overlap，观察召回变化。
3. **Indexing**：将 chunk、embedding 和 metadata 写入 pgvector，理解向量表结构。
4. **Retrieval**：先做 top-k 余弦相似度检索，再加入 collection、tag、时间过滤。
5. **Generation**：把检索结果作为上下文交给 ChatModel，回答必须返回引用来源。
6. **评估**：准备 20 个真实问题，记录 Recall@k、引用准确率和无答案时的拒答率。
7. **Agent**：最后再让 AI 管家调用搜索、总结、新建待办等工具，避免用 Agent 掩盖 RAG 的检索问题。

## 当前 RAG 数据流

```text
笔记原文（notes）
    -> LangChain4j DocumentSplitter
    -> 本地 BGE-M3 Embedding 服务（1024 维）
    -> pgvector（knowledge_embeddings）
    -> 相似度检索 + metadata 过滤
    -> ChatModel 结合上下文回答
    -> 返回笔记引用
```

后端使用 Java 17、Spring Boot 3.4 和 LangChain4j。本地 Embedding 服务配置见 [本地嵌入服务.md](本地嵌入服务.md)。

## Embedding 模型选择

当前默认使用本地 `BAAI/bge-m3`（1024 维）。它通过 OpenAI 兼容接口提供 embedding，LangChain4j 无需直接加载模型：

| 模型 | 维度 | 适用场景 |
| --- | ---: | --- |
| `text-embedding-3-small` | 1536 | 云端 API，成本和效果均衡，适合第一阶段 |
| `BAAI/bge-m3` | 1024 | 中文与多语言、本地部署，适合第二阶段重点学习 |
| `bge-large-zh-v1.5` | 1024 | 更偏中文检索质量 |
| `bge-small-zh-v1.5` | 512 | 本地资源有限、强调速度 |

模型、维度和向量数据必须配套。更换 embedding 模型后，不能继续复用旧向量；需要修改 `PGVECTOR_DIMENSION`，重建 `knowledge_embeddings` 表，并重新处理全部笔记。不要在同一向量列中混合不同模型生成的 embedding。
