# 后端实施清单

本文档是知序后端的实施大纲。整体架构见 [整体架构.md](整体架构.md)，运行参数见 [参数台账.md](参数台账.md)。

## 1. 第一阶段：基础工程与数据库

- [x] 建立 Java 17 + Spring Boot 3.4 工程。
- [x] 接入 LangChain4j、PostgreSQL 和 pgvector。
- [x] 配置本地 BGE-M3 OpenAI 兼容 Embedding 接口。
- [x] 增加 `/api/health` 健康检查。
- [ ] 使用 Flyway 替换 `schema.sql`，建立可追踪的数据库迁移。
- [ ] 创建 `collections`、`notes`、`tags`、`note_tags` 表。
- [ ] 为笔记增加 `index_status`、`index_version` 和软删除字段。

验收标准：应用可以连接 `testdb`，启动时验证 `vector` 扩展，健康接口能分别报告数据库和 Embedding 服务状态。

## 2. 第二阶段：笔记业务 API

- [x] 实现知识空间基础列表、创建和删除（`/api/v1/spaces`）。
- [x] 实现云端个人资料更新与知识空间改名。
- [x] 实现笔记创建、详情、修改、软删除和列表（`/api/v1/spaces/{spaceId}/notes`、`/api/v1/notes/{id}`）。
- [x] 实现收藏字段更新；标签仍待独立建模。
- [x] 实现标题/正文关键词搜索（列表接口 `q` 参数）。
- [ ] 将当前 Map 响应收敛为稳定 DTO，避免长期直接返回行映射。
- [x] 更新笔记使用 `revision` 乐观锁，防止编辑覆盖。

计划 API：

```text
GET    /api/collections
POST   /api/collections
GET    /api/notes
POST   /api/notes
GET    /api/notes/{id}
PUT    /api/notes/{id}
DELETE /api/notes/{id}
GET    /api/notes/search?q=...&limit=...
```

验收标准：前端不再依赖 `localStorage` 模拟数据，能够完整管理笔记，并有 Repository/Service/API 分层测试。

## 2.5 本地优先与云同步

- [x] SQLite 笔记改为稳定 UUID、逐条 CRUD 和事务性入队。
- [x] 增加 `revision`、`updated_at`、`deleted_at`、`sync_status`。
- [x] SQLite 建立 `sync_queue`，业务写入与队列写入同一事务。
- [ ] 后端实现批量 push/pull 同步 API。
- [x] PostgreSQL 单条更新使用 revision 检测冲突，客户端提供显式冲突处理；批量协议仍待实现。
- [ ] 文件元数据同步不传本机绝对路径。
- [ ] 附件上传与业务对象同步拆分，使用 SHA-256 去重。

验收标准：断网可正常编辑；恢复网络后增量同步；两端并发修改会进入明确冲突流程，不上传整个 SQLite 文件。

## 3. 第三阶段：文档摄取与向量索引

- [x] 建立 `RagPipeline` 文档切块、Embedding 和 pgvector 写入链路。
- [ ] 将摄取逻辑拆到 `ingestion` 模块。
- [x] 支持 Markdown、TXT 上传并保存原文；PDF/DOCX 仍待解析器接入。
- [ ] 定义统一 `DocumentParser`，接入 PDFBox、Apache POI，之后再接 Tika/OCR。
- [ ] 源文件保存在用户目录或对象存储，PostgreSQL 只保存元数据/object key。
- [ ] 文档区分 `parse_status`、`index_status`、`sync_status`。
- [x] 文档向量保存 `document_id`、`owner_id`、`space_id`、标题、文件名和 MIME metadata；chunk index/页码待补充。
- [x] 实现文档上传、重试、删除和空间删除时的向量同步；云端笔记向量化待补充。
- [ ] 实现“仅移出 AI”“删除云端”“删除本地”“彻底删除”四种范围。
- [x] 建立摄取任务状态、失败原因和重试接口，并调用 `RagPipeline` 完成索引。
- [ ] 批量调用 BGE-M3，避免逐条请求造成性能浪费。
- [ ] 记录 embedding 模型、维度、切块参数和索引版本。

验收标准：任意笔记都可以被完整索引、重新索引和删除索引；Embedding 服务中断不会导致原文丢失。

## 5. 第五阶段：MCP 接入

MCP 分为两个独立角色：

```text
AI / MCP Client
       |
       | MCP stdio（第一阶段）
       v
zhixu-mcp-server
       |
       | 受控 HTTP API
       v
zhixu-backend
       |
       v
PostgreSQL + pgvector / BGE-M3
```

### MCP Server

- [x] 在根目录建立独立 `mcp-server/` 项目。
- [x] 使用官方 TypeScript MCP SDK 和 stdio transport。
- [x] 定义 `health_check`、`search_notes`、`get_note` 工具骨架。
- [ ] 后端完成笔记 API 后进行真实联调。
- [ ] 增加 `search_knowledge` 语义检索工具。
- [ ] 增加写入工具前的确认参数、幂等键和审计记录。
- [ ] 需要跨机器调用时再增加 Streamable HTTP、鉴权和 TLS。

### 主后端作为 MCP Client

- [ ] 选定与当前 LangChain4j 版本兼容的 MCP Client 实现；必要时升级 LangChain4j。
- [ ] 建立 `mcp` 模块，负责 Server 注册、连接生命周期和工具发现。
- [ ] 将 MCP Tool 转换为 Chat Model 可调用的工具定义。
- [ ] 按用户会话建立工具白名单；默认只允许只读工具。
- [ ] 工具调用设置超时、最大返回大小、重试和熔断。
- [ ] 将工具调用名称、参数摘要、耗时和结果状态写入审计日志。
- [ ] 写操作在前端显示确认界面，用户确认后才执行。

MCP 验收标准：主后端或桌面 MCP Client 可以发现三个只读工具；搜索和读取结果受后端权限控制；MCP Server 停止时不影响普通笔记功能。

## 6. 第六阶段：AI 管家与 Agent

- [ ] 把搜索知识、读取笔记、创建草稿、管理待办封装为明确工具。
- [ ] 区分只读、可撤销写入和高风险操作。
- [ ] 限制最大工具调用轮数，防止无限循环。
- [ ] 关键写操作要求用户确认，不允许模型自行授权。
- [ ] 保存工具执行结果和来源，回答仍要附引用。

验收标准：Agent 只通过业务服务或 MCP 工具行动，不能直接拼接 SQL 或绕过权限。

## 实施顺序

严格按 `笔记 CRUD -> 索引同步 -> 检索 API -> 带引用问答 -> MCP 联调 -> Agent` 推进。MCP 是工具协议，不替代业务 API、RAG 或权限系统。
