## 已完成联调

- `POST /api/v1/auth/login`：前端登录页已调用真实后端。
- `GET /api/v1/auth/me`：登录后获取用户和个人空间。
- `POST /api/v1/auth/logout`：退出时撤销后端 refresh token。
- `GET /api/v1/spaces/{spaceId}/notes`：登录后从 PG `notes_v1` 加载笔记。
- `POST /api/v1/spaces/{spaceId}/notes`：新建笔记写入 PG。
- `PUT /api/v1/notes/{noteId}`：收藏状态携带 revision 写回 PG。
- `POST /api/v1/spaces/{spaceId}/documents`：Markdown/TXT 上传到 PG `documents`，创建 `ingestion_jobs`。
- 前端开发环境通过 Vite `/api` proxy 访问后端。
- Tauri 发布版通过 `http://localhost:8080` 访问后端，并配置 CSP。
- 后端已增加仅允许本机 Vite/Tauri 来源的 CORS 配置。

## 当前后端仍未完成

以下内容不能在前端标为“已可用”：

- PDF、DOCX 解析。当前 `DocumentService` 只接受 Markdown/TXT。
- 文档处理任务调用 `RagPipeline.ingest`。当前任务只更新状态，没有生成向量。
- 新增/修改/删除笔记时同步更新 `knowledge_embeddings`。
- pgvector Top-K 检索 API。
- Chat Model 和真实 RAG 问答 API。
- SSE 流式回答和 citations。
- 用户资料更新 API。个人签名当前仍保存在桌面本地 SQLite。
- 桌面离线 outbox 和云端同步冲突处理。

因此当前 AI 管家仍是前端关键词模拟，不应宣称已经调用大模型。

## 后端下一步提示

请在 `D:\KnoweldgeOrder\backend` 按这个顺序实现：

1. 在 `DocumentService.process` 中调用 `RagPipeline.ingest`，metadata 至少含 `document_id/note_id`、chunk index、标题和空间。
2. 新建、更新、删除笔记时同步新增、重建、删除相应向量；失败时保留原文并记录索引状态。
3. 实现 `POST /api/v1/retrieval/search`，返回 score、chunk、来源 ID 和标题。
4. 接入可配置 Chat Model，实现 `POST /api/v1/chat`。
5. 实现 SSE 流式接口，事件包含 delta、citation、completed、error。
6. 增加 PDF/DOCX 解析器，保留页码和标题层级。
7. 增加 `PUT /api/v1/auth/profile`，保存 display name、bio 和默认空间名称。
8. 使用 Flyway 替换启动时重复执行 `schema.sql`。
9. 为 CRUD、上传、权限、索引和检索增加 PostgreSQL 集成测试。

## 验收要求

- 新建笔记后可直接在 PG `notes_v1` 查询到。
- 上传 Markdown/TXT 后 job 最终进入 `ready`；向量表能按来源 ID查到 chunks。
- 更新笔记后旧向量不再被检索。
- 没有可信来源时 RAG 明确拒答。
- 每条回答引用可点击回到真实笔记或文档。
- BGE-M3 不可用时原文仍已保存，任务进入可重试失败状态。
- 所有资源查询按登录用户和空间隔离。
